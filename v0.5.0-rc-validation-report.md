## Named RC defect repairs

### Codex task-title normalization

The historical issue #61 task requested:

```text
🕷️ B6 · Prevent stale plugin installs and preserve provenance
```

That is 61 Unicode code points and 62 UTF-16 code units. Codex stored the
60-code-unit title `🕷️ B6 · Prevent stale plugin installs and preserve provena…`.
The previous strict equality check retried that non-actionable mismatch and
eventually left otherwise successful terminal work at
`member-evidence-requires-review`.

The repair adds one shared, fail-closed equivalence rule: accept exact equality
or the exact Codex 60-code-unit ellipsis normalization. Arbitrary prefixes,
different suffixes, and every other mismatch still fail. Both initial launch
batch verification and later orchestration observation use the same rule.
Focused regressions reproduce the 61-character title at both boundaries and
prove a near-prefix mismatch is still rejected.

### Blank execution-map widget

The blank body was reproducible when a valid execution map arrived after the
widget's one-time `window.openai.toolOutput` sample through
`openai:set_globals`; the prior widget did not listen for that bridge update and
began with an empty list. Wave 3 also found that the MCP Inspector verifier was
stale at resource URI `execution-map-v7.html` while the candidate correctly
advertised `execution-map-v8.html`, and that it still expected one protocol
schema at its pre-execution-map nesting.

The repair listens to both the standard MCP Apps
`ui/notifications/tool-result` notification and OpenAI globals updates, accepts
either a direct structured payload or a complete tool result, and starts with a
nonblank waiting state. The verifier now imports the production URI, MIME type,
and complete 11-tool binding set and checks the nested protocol schemas.

The automated DOM regression executes the actual inline production resource:
a valid `running` map received through MCP Apps renders one running member, and
a later valid `accepted` map received through OpenAI globals replaces it with
one accepted member. The official SDK fixture test verifies the structured
payload and resource bytes, MCP Inspector verifies tool/resource bindings, and
the pinned official reference host commit
`92f46a574568a3ddac7600343b7d3c4c4ed7b588` builds and reaches its host,
sandbox, and fixture endpoints. The environment exposed no controllable browser
instance for an additional manual screenshot, so no screenshot is claimed;
protocol, host, and actual DOM-render evidence are automated release gates.
